================================================================================
SERAYA STATIC SITE -> SPACESHIP DOMAIN + CLOUDFLARE PAGES (RECOMMENDED)
================================================================================

WHAT YOU NEED
--------------------------------------------------------------------------------
1) This folder (all HTML, styles.css, script.js, assets) on Cloudflare Pages.
2) Your domain registered at Spaceship; DNS either on Cloudflare (best) or at
   Spaceship using the records Cloudflare Pages shows for a custom domain.

Spaceship sells domains; Cloudflare Pages hosts the files and HTTPS.

BEFORE UPLOAD / GIT PUSH
--------------------------------------------------------------------------------
- Save every .html, .css, .js as UTF-8 (NOT UTF-16 / "Unicode" in Notepad).
- Keep index.html at the site root (same folder as styles.css).
- This repo includes _headers for Cloudflare Pages (charset on HTML/CSS/JS).
- netlify.toml is only needed if you use Netlify; Cloudflare ignores it.

================================================================================
OPTION A - CLOUDFLARE PAGES (Git connected) — RECOMMENDED
================================================================================
1. Push this repo to GitHub (or GitLab / Bitbucket supported by Cloudflare).

2. Cloudflare Dashboard -> Workers & Pages -> Create application -> Pages ->
   Connect to Git -> authorize and select the repo.

3. Build settings (static site, no framework):
   - Framework preset: None
   - Build command: (leave empty)
   - Build output directory: /   (root — the folder that contains index.html)
   OR if the UI requires a name, use "." or "/" per Cloudflare's hint for root.

4. Save and Deploy. You get https://<project-name>.pages.dev

5. Custom domain:
   - Workers & Pages -> your project -> Custom domains -> Set up a custom domain.
   - Add yourdomain.com (and optionally www).

6. DNS — pick ONE approach:

   (6A) USE CLOUDFLARE NAMESERVERS (simplest SSL + one dashboard)
   ---------------------------------------------------------
   a. Cloudflare Dashboard -> Add a site -> enter yourdomain.com -> Free plan.
   b. Cloudflare shows two nameservers (e.g. xxx.ns.cloudflare.com).
   c. Spaceship: Domain -> your domain -> Nameservers -> Custom / Change ->
      paste Cloudflare's two nameservers only (replaces Spaceship DNS).
   d. Wait until DNS propagates (often under an hour).
   e. In Pages -> Custom domains: add yourdomain.com — Cloudflare can auto-create
      the needed DNS records on the same account.

   (6B) KEEP DNS AT SPACESHIP
   ---------------------------------------------------------
   - After adding the custom domain in Pages, Cloudflare shows the exact records
     (usually CNAME for www -> <project>.pages.dev).
   - For apex (yourdomain.com without www): use whatever Spaceship supports
     (ALIAS/ANAME to <project>.pages.dev), or redirect apex to https://www... in
     Spaceship's URL forwarding, or move nameservers to Cloudflare (6A).

7. Wait for SSL: Pages issues certificates once DNS is correct.

================================================================================
OPTION B - CLOUDFLARE PAGES (Upload / Wrangler, no Git)
================================================================================
1. Install Node.js if needed. From THIS folder (where index.html lives):

      npx wrangler pages deploy . --project-name=YOUR_PROJECT_NAME

   First time: log in to Cloudflare when Wrangler prompts. Create the project
   name in the dashboard or let Wrangler create one.

2. wrangler.toml in this folder is set for Workers Static Assets (wrangler deploy).
   If the dashboard build command is `npx wrangler deploy`, this file must include
   compatibility_date and [assets] directory (see wrangler.toml). Do not mix with
   a Pages-only wrangler that only had pages_build_output_dir — that triggers the
   deploy error you saw.

3. Custom domain + DNS: same as steps 5–7 in Option A.

================================================================================
WORKER (STATIC ASSETS) ON YOUR MAIN DOMAIN — APEX + HTTPS
================================================================================
This applies when the site is deployed as a Cloudflare **Worker** with
`npx wrangler deploy` and `[assets]` in wrangler.toml (this repo).

PREREQUISITE
--------------------------------------------------------------------------------
The hostname must live in an **active Cloudflare zone** on the same account as
the Worker. Custom Domains cannot attach to a domain whose DNS you only manage
at Spaceship unless that domain also uses Cloudflare as DNS.

1) Cloudflare Dashboard -> Add a site -> enter your root domain -> continue.
2) At Spaceship: set **nameservers** for the domain to the two Cloudflare
   nameservers (replaces Spaceship DNS). Wait until the zone shows Active.

CLOUDFLARE DASHBOARD (easiest)
--------------------------------------------------------------------------------
1. Workers & Pages -> select your Worker (e.g. seraya-static-site).
2. Settings -> **Domains & Routes** -> **Add** -> **Custom Domain**.
3. Enter your **main domain** exactly: `yourdomain.com` (no `https://`, no path).
4. Confirm. Cloudflare creates DNS + edge certificate for that hostname.

WWW VS APEX
--------------------------------------------------------------------------------
A Custom Domain is an **exact hostname** match. `yourdomain.com` and
`www.yourdomain.com` are two hostnames.

- To serve the Worker on **both**: add **two** Custom Domains (apex and www).
- To use **only apex** and redirect www: add Custom Domain for apex only, then
  use a Cloudflare **Single Redirect** rule (www -> root). You need a proxied
  placeholder DNS record on `www` for the redirect to apply; see:
  https://developers.cloudflare.com/rules/url-forwarding/examples/redirect-www-to-root/

WRANGLER (optional — keeps domains in git)
--------------------------------------------------------------------------------
After the zone exists on Cloudflare, you can add to wrangler.toml (replace with
your real domain), then `npx wrangler deploy`:

   [[routes]]
   pattern = "yourdomain.com"
   custom_domain = true

   [[routes]]
   pattern = "www.yourdomain.com"
   custom_domain = true

If you later change domains only in the dashboard, the next deploy may overwrite
routes defined in wrangler.toml — pick one place as source of truth.

CONFLICTS TO AVOID
--------------------------------------------------------------------------------
- You cannot add a Custom Domain on a hostname that already has a **CNAME** you
  rely on for something else; remove or replace conflicting records per Cloudflare
  prompts when adding the domain.
- Do not point apex at a different host (A record to old server) while expecting
  the Worker Custom Domain to take over — follow the dashboard’s DNS updates.
